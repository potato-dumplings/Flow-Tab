## Purpose

This document gives a product-scenario view of FlowTab test coverage. It complements the existing layer-focused documents:

- [UNIT_AND_BEHAVIOR_TEST_COVERAGE.md](UNIT_AND_BEHAVIOR_TEST_COVERAGE.md)

Use this matrix when deciding whether a feature has enough automated evidence across unit, behavior/integration, and UI/end-to-end layers.

## Status Legend

- `Strong`: the layer has direct automated coverage for the scenario.
- `Partial`: the layer has related automated coverage, but it does not prove the full user-visible or runtime outcome.
- `Not relevant`: the layer does not naturally apply to this scenario.
- `Gap`: the scenario still needs coverage in this layer.

## Recent Validation Notes

- 2026-06-17 Phase 5: `LiveSwitcherModel` now stores and uses its runtime dependency as `runtimeProjectionService`, so Switcher internals and constructor injection describe projection reads, dirty signals, committed Search-index reads, freshness-barrier requests, termination cleanup, and verified-focus writeback as projection-runtime ownership rather than a surface snapshot service.
- 2026-06-17 Phase 5: Home projection-reader ownership no longer lives in a snapshot-named source file. `HomeRuntimeSnapshotService.swift` was renamed to `HomeRuntimeProjectionService.swift`, and the Home initial first-frame reader now exposes `initialAppSummaries` / `appSummaries` instead of `lightweightAppSummaries`, preserving the old lightweight snapshot fallback only as a regression oracle in test names and documentation.
- 2026-06-17 Phase 5: Home surface runtime injection now uses projection wording (`homeRuntimeProjectionService`, `runtimeProjectionService`) and the Home no-window transient-rebuild check reads through the injected projection service instead of the global shared runtime instance. This keeps Home's surface boundary aligned with projection-read/dirty-signal ownership, now through the `RuntimeProjectionServing` contract.
- 2026-06-17 Phase 5: Search stale committed-index reads now report `degradedStaleCommittedResult` and `committedIndexCoversCurrentGeneration=0` in the Search-facing diagnostic/log path. A stale committed index can still provide degraded results while requesting the bounded freshness barrier, but until that barrier commits a new generation it is explicitly not `latestCommittedResult` and is no longer named or logged as `freshResult` / `completeResult`.
- 2026-06-18 Phase 5: Search stale committed-index diagnostics now assert the barrier-not-committed path is not logged as `latestCommittedResult`, `freshResult`, or `completeResult`; the current behavior remains degraded/stale committed result plus dirty/freshness metadata until a scoped repair commits a new generation.
- 2026-06-17 Phase 5: `RuntimeCurrentAppWindowPayload` and `RuntimeCurrentAppWindowProjection` no longer expose Home snapshot compatibility initializers or accessors. Provider repair conversion is isolated inside `RuntimeProjectionService`, and Home surface readers now return `RuntimeHomeAppDetailProjection` instead of rebuilding a legacy Home snapshot shape at the projection-reader boundary.
- 2026-06-17 Phase 5: `RuntimeCurrentAppWindowProjection` construction now requires `RuntimeCurrentAppWindowPayload`; the previous `homeAppSnapshot:` projection initializer was removed and current-app projection test fixtures now wrap provider repair payloads before entering the projection boundary.
- 2026-06-17 Phase 5: Runtime reconciliation completion now hands `RuntimeCurrentAppWindowPayload` into `RuntimeProjectionService`/`RuntimeReadModelStore`, and `RuntimeReadModelStore.commitCurrentAppWindowProjection(...)` no longer accepts a Home snapshot-shaped write boundary. Provider repair primitives convert `RuntimeAppWindowRepairPayload` into current-app payloads before committing current-app/search projections.
- 2026-06-17 Phase 5: Switcher focused-current-app startup and selected-app window projection completion now consume `RuntimeCurrentAppWindowPayload` directly, with recency applied to the payload before session construction. The provider repair payload remains outside the Switcher and Home projection read payload.
- 2026-06-16 Phase 5: `RuntimeReadModelStore` now proves current-app repair snapshots upsert the app switcher projection, and `RuntimeProjectionService` proves launched-app repair snapshots commit into the app switcher projection before hot-path reads depend on it.
- 2026-06-16 Phase 5: the Space fixture workflow now builds bundle-id-scoped app bundle paths and the UI wrapper validates each fixture bundle path plus `Info.plist` bundle identifier before reuse, preventing stale LaunchServices/app-path contamination from hiding real runtime ownership failures.
- 2026-06-16 Phase 5: the four-window Noisy Option+Tab fixture now asserts real `collectCGWindows` Space signature diagnostics (`signatureChanged`, display/space/window/fullscreen counts, and signature summary) after activation, closing the representative Space signature real UI proof gap while broader multi-display/system-owner and stale projection race coverage remain open.
- 2026-06-16 Phase 5: `scripts/perf/runtime-topology-pressure.sh` now provides a repeatable external CPU/RSS wrapper for the Noisy Option+Tab real topology path. A non-sandbox rerun passed with 70 samples at 0.5s cadence (`cpuAvg=29.37`, `cpuP95=59.50`, `cpuMax=84.70`, `rssAvgMB=112.12`, `rssP95MB=174.67`, `rssMaxMB=202.70`); an earlier wrapper attempt exposed a dirty app-switcher projection stale-window race, so that race remains a concrete gap rather than being counted as closed by the passing baseline.
