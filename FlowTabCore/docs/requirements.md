# FlowTab 功能需求（V0）

## 目标

在 macOS 上提供可分组的应用切换体验，作为 `Command + Tab` 的增强或替代方案。

## 产品定位与发布约束

- 产品形态：开源、免费工具。
- 发布渠道：非 Mac App Store 分发。
- 技术约束影响：
  - 可根据实现效果评估并使用必要的私有 API，以提升 `Command + Tab` 替代能力。
  - 需明确兼容性策略：macOS 版本升级后，私有 API 变更可能导致行为回退或失效。

## 功能清单

### 1. 最小化应用是否参与切换（可选项）

- 背景：macOS 原生在某些场景下不会直接恢复最小化窗口，影响切换连贯性。
- 需求：
  - 提供一个可配置开关：`切换时自动恢复最小化应用`。
  - 开关关闭时：保持接近原生行为，不主动恢复最小化窗口。
  - 开关开启时：当目标应用仅有最小化窗口时，切换后应自动恢复并激活对应窗口。
- 默认值（建议）：`开启`（可在实现阶段再确认）。

### 2. 快捷键与分组切换规则

- 主切换快捷键：
  - 默认覆盖：`Command + Tab`。
  - 允许用户自定义为其他组合键。
- 分组切换快捷键：
  - 在按住主组合键时，`↑` 进入分组导航模式（聚焦当前应用所在分组）。
  - `← / →` 在分组之间切换。
  - `Tab` 在当前分组内按顺序切换应用（保留主切换手感）。
- 释放键行为：
  - 释放主修饰键（`Command`）后，确认当前选中项并执行切换。

### 3. 单应用多窗口切换交互

- 目标：当一个应用存在多个窗口时，不仅停留在“最后打开/最近活跃”窗口，而是允许快速切换到该应用的其他窗口。
- 层级交互：
  - 一级：`Command + Tab` 保持应用级切换（默认落到该应用最近活跃窗口）。
  - 二级：选中某应用后，按 `↓` 进入该应用窗口级切换（仅当窗口数 >= 2）。
- 二级按键规则：
  - `Tab / Shift + Tab`：在该应用窗口列表中前进/后退。
  - `↑`：返回上一级（应用/分组级）。
  - 释放 `Command`：确认到当前高亮窗口并激活。
- 配置项：`多窗口切换策略`
  - `最近活跃窗口（默认）`
  - `记住上次选中的窗口`
  - `有多窗口时自动进入窗口层`

### 4. 视觉与交互风格（macOS 简洁风）

- 整体设计应体现 macOS 独有的简洁感：信息克制、层级清楚、动效轻量、反馈明确。
- 视觉原则：
  - 优先使用系统语义与系统控件风格，避免花哨装饰和强干扰色块。
  - 保持低噪音界面：减少不必要文本和边框，突出当前选择态。
  - 采用统一圆角、间距与阴影节奏，保证界面观感一致。
- 交互原则：
  - 操作路径短，键盘优先，不要求用户进行多余确认。
  - 动画以“状态过渡可理解”为目标，避免炫技型动效。
  - 不打断工作流：面板应快速出现/消失，切换反馈应即时。
- 主题模式：
  - 仅支持三种主题：`白天`、`黑夜`、`跟随系统`。
  - 默认主题：`跟随系统`。

## 待确认项

- 默认是否开启“自动恢复最小化应用”。
- 分组切换时是否支持循环（最后一组再向右回到第一组）。
- 在分组模式下是否允许 `Shift + Tab` 逆序切换组内应用。
- 主快捷键冲突时的处理策略（提示用户改键或自动降级）。
- 窗口级列表的排序规则（最近活跃优先 / 打开时间顺序）。
