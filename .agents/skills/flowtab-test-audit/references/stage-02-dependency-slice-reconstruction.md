# Stage 02: Dependency Slice Asset Reconstruction

## Outcome

Reconstruct and close exactly one minimal dependency slice. Establish a committed C1 that identifies the authoritative canonical validation-plan rows and records generated test assets, validation and rollback boundary.

## Entry

- Require the current committed C0, empty-boundary evidence, production snapshot, shared-rule snapshot, boundary hash, validation-plan hash and dependency inputs.
- Select one entry-ready slice with satisfied prerequisites, stable production ownership and explicit dirty-path ownership.
- Inherit the Campaign `commit_policy`; use the frozen standalone policy when Stage 02 was explicitly started alone.
- Verify that the current candidate contains only assets generated by committed C1 slices after C0.

## Work

1. **Protected behavior.** Confirm the slice's expected result from production routing plus an independent product, API, platform or observation Oracle.
2. **Scenario family.** Fan out state, input, topology, lifecycle, persistence, permissions, fallback and scale. Select Required representatives and record Optional variants.
3. **Module boundary.** Confirm production Owner, dependency direction, consumers, interaction peers and invalidation propagation.
4. **Asset design.** Assign distinct Unit, Behavior, Mock UI, real-topology UI and Pressure responsibilities. Define the required test source, Fixture, TestingSupport, Runner, prerequisite and configuration assets.
5. **Generation.** Capture the current slice scope as `.build-local/test-audit/rebuild/slices/<slice-id>/BEFORE_ASSETS.jsonl`, generate the smallest complete asset set, then capture `AFTER_ASSETS.jsonl` and canonical `ASSET_DELTAS.jsonl`.
6. **Plan references.** Update the selected canonical rows with the confirmed slice decisions, validate the complete plan and generate `VALIDATION_PLAN_REFS.json`. Preserve the complete plan's input/output hashes, each selected row SHA-256 and the selected-row aggregate SHA-256.
7. **Validation.** Execute every Required row through the reconstructed canonical Runners. Record observations, evidence identities, environment identity, Skip/Flake classification and remaining uncertainty beneath the transient root.

Create `docs/test-audit/slices/<slice-id>/SLICE_HANDOFF.json` as the draft C1 with:

- C0, production snapshot, shared-rule snapshot and boundary hash;
- slice ID, scope, Owner, prerequisites and disposition;
- validation-plan input/output hashes, selected row IDs, canonical row hashes and selected-row aggregate hash;
- concise behavior and Oracle decision outcomes that point to those rows;
- generated asset paths and canonical delta hash;
- per-layer validation and decisive evidence;
- dependency and interaction invalidations;
- remaining uncertainty, next-slice hints and rollback boundary.

Use engineering's semantic guard when a reopened slice would change a behavior already confirmed by a committed current C1. Initial generation from the empty boundary is additive.

## Completion Eligibility

- Confirm the protected behavior, authoritative Owner, independent Oracle and actual production path.
- Generate every asset required by the slice without importing prior-Campaign test contents.
- Resolve every dependency owned by the selected slice against its current asset records; leave later-slice dependencies only where the C0 DAG explicitly schedules them downstream.
- Match the generated assets and delta to the validation plan.
- Regenerate the selected validation-plan references byte-for-byte, match their aggregate hash to C1 and prove the complete plan hash transition from the input anchor.
- Satisfy every Required validation row or retain a current evidenced blocker.
- Resolve unexpected Skip, open Flake, stale evidence, temporary diagnostics and dependency invalidations.
- Validate canonical before, after, delta and observation records beneath `.build-local`.
- Resolve every `unresolved` asset-lineage candidate before classifying a move, rename, merge or split.
- Freeze C1, its selected row references and its exact generated asset and anchor set.

## Commit

- Commit one minimal reconstructed slice, its test-owned project fragments and current C1.
- Select the semantic commit type from the generated asset delta.
- Apply the shared policy after all applicable runtime and Process/Tooling validation passes.
- Use the resulting commit as the C1 consumed by Stage 03.

## Blocked And Resume

- Return stale C0, rules, boundary or dependency inputs to Stage 03 for readiness recomputation.
- Stop before generation when protected behavior, Owner or Oracle is insufficient.
- Return stale or mismatched validation-plan row references to the slice plan step.
- Resume a Required environment blocker at its validation row while retaining current lower-layer evidence.
- Reopen a committed C1 through engineering's semantic guard when its confirmed behavior must change.
- Preserve an eligible candidate after a Commit failure and resume at Commit while its parent and exact file set remain current.
